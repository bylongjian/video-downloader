# 万能视频下载总结器：SEO 与 GEO 上线前优化方案

当前网站主要靠浏览器运行 JavaScript 后展示内容，搜索引擎和部分 AI 抓取工具可能只能拿到空的应用容器。本轮先让公开介绍能被直接读取，再把真实功能整理成便于引用的使用说明；保留已有的视频、账号、额度、历史、队列和会员流程。

方案日期：2026-11-02。主流程：Superpowers。状态：用户已确认方案；SEO、GEO 两阶段均已实施、验证及清理；结果见《SEO与GEO运行及验收》。用户已确认“暂无域名，先做上线前优化”。实施验收阶段不提交、推送或发布；后续用户已明确要求保存 Git 记录，本次按授权提交，不推送或发布。

## 1. 需求小卡

用户将能在不改变现有使用流程的前提下，得到可检查的页面标题、分享信息和公开说明。上线前只能验证技术准备情况；真实搜索收录、排名和 AI 引用需要网站公开后持续观察。

| 项目 | 预期 |
| --- | --- |
| 要解决的问题 | 首页正文依赖 JavaScript，缺少完整的页面信息、抓取规则和规范网址配置 |
| 最重要的预期 1 | 生产构建的首页 HTML 直接包含真实介绍、操作步骤与常见问题，不只含空容器 |
| 最重要的预期 2 | 每类已有页面有相应的标题和描述；工作台、历史、队列、会员订单不进入公开网站地图，并标记不收录 |
| 最重要的预期 3 | 没有域名时不生成占位域名、localhost 或当前预览地址作为 canonical、分享绝对网址或 sitemap 链接 |
| 最重要的预期 4 | 先完成 SEO 的实现、验证和临时材料清理，再开始 GEO |

| 已确认的关键内容 | 对外名称采用“SaveAny（万能视频下载总结器）”；同意下文公开内容范围与测试清理范围 |

## 2. 实现方式选择

推荐在现有 Vue + Vite 项目上增加构建时静态输出。公开介绍可以复用现有组件，避免维护两份不同的功能说明；账号及工作台仍按现有方式运行。

| 方式 | 收益 | 改动与取舍 |
| --- | --- | --- |
| 仅补充 meta 标签 | 改动最少 | 不能解决不运行 JavaScript 时读不到正文的问题 |
| 构建时输出公开 HTML，推荐 | 正文与页面信息可直接抓取，不需要新增线上渲染服务 | 需要调整构建步骤，验证首页启动和已有路由 |
| 迁移到完整服务端渲染框架 | 适合大量动态公开内容 | 当前主要动态内容属于个人数据，迁移范围和回归风险较大 |

Vue 官方说明中，构建时渲染需要避免在渲染阶段访问 window、document 等浏览器接口。为此仅渲染公开介绍组件，不在构建时执行现有账号、视频解析或支付流程。参考：[Vue 服务端渲染指南](https://vuejs.org/guide/scaling-up/ssr)。

## 3. SEO 阶段设计

建议保留现有 SaveAny 标识，同时用中文说明产品是什么。下面是文案示意，并非搜索引擎实际展示截图，也不代表已被收录。

| 位置 | 建议内容 |

| 首页 title | 万能视频下载总结器 - SaveAny \| 视频下载与 AI 学习助手 |
| 首页 description | SaveAny 万能视频下载总结器提供视频链接解析、可用格式下载、字幕导出与 AI 摘要、思维导图和视频问答。游客可解析和单条下载；登录后使用 AI、历史和批量任务。平台可用性受视频权限、网络与服务配置影响。 |
| 关键词方向 | 万能视频下载总结器、SaveAny、视频下载、AI 视频总结、字幕导出、思维导图、视频问答 |
| 首页正文主题 | 视频下载与 AI 总结；保留现有首页结构，只作必要的语义和文案调整 |

平台文案说明依赖 yt-dlp 的实际支持及平台访问条件，不把“1800+ 平台”写成逐一验证通过。清晰度以源视频返回的可用格式为准。保留现有免费额度、30 分钟单条转写上限及 Stripe 测试商品说明。

### 3.2 页面与抓取范围

只公开产品介绍和使用帮助。视频来源链接、个人总结、字幕、任务与订单不会写入静态 HTML、结构化数据或网站地图。

| 页面 | 页面信息 | 生产环境索引策略 |
| --- | --- | --- |
| `/` | 独立标题、描述、关键词、OG、Twitter 分享信息与网站结构化数据 | 配置正式域名后允许索引 |
| `/workbench` 及查询参数 | 视频工作台的通用标题和描述，不包含用户视频标题或链接 | 不索引 |
| `/history` 及详情 | 我的历史的通用标题和描述 | 不索引 |
| `/queue` | 批量任务的通用标题和描述 | 不索引 |
| `/billing` 及订单回跳参数 | 会员与订单的通用标题和描述 | 不索引 |
| 未知路径 | 返回真实 404，提供回到首页的入口 | 不索引 |

在首个 HTTP 响应中输出相应的抓取控制，避免只靠 JavaScript 补上 noindex。robots.txt 不是隐私保护机制，现有后端鉴权继续负责访问权限。不能误拦截网站公开页面需要的 CSS、JavaScript 和图片。

### 3.3 没有域名时如何处理

增加统一的公开站点地址配置，并在普通构建与 Docker 构建中使用同一来源。未配置时仍可启动和构建，公开文案可本地审阅，但明确处于上线前状态。

| 状态 | 行为 |
| --- | --- |
| 没有正式网址 | 不生成 canonical、og:url、绝对分享图片地址或 sitemap.xml；爬虫规则和页面信息设置为不索引 |
| 配置正式 HTTPS 根网址后 | 生成一致的 canonical、绝对分享地址与 sitemap.xml；公开页允许索引，个人功能页继续不索引 |
| 配置格式错误 | 在构建入口给出清楚的错误，不生成混用域名的产物 |
| 本地开发、临时预览 | 不自动把当前浏览器地址当成正式站点；测试用网址仅出现在临时隔离构建中 |

网站地图只列公开页面，不写私人路由、查询参数和虚构更新时间。站点没有新旧地址迁移需求，不新增无依据的重定向。

### 3.4 文件与业务边界

预计调整前端首页组件、页面信息模块、Vite 构建入口、HTML 模板与部署静态路由，增加分享图片和配置示例。后端业务代码、真实配置、数据库、下载文件和模型保持原状。

首页现有交互事件继续连接 App.vue，解析、下载与登录逻辑不搬到预渲染入口。公开文字由同一份内容驱动，首屏不会同时显示两份介绍。

## 4. SEO 验证与清理

这一阶段必须验证实际产物和原有功能，而不只检查源代码里有没有标签。先记录结果并清理本轮临时材料，再进入 GEO。

| 验证 | 完成标准 |
| --- | --- |
| 无域名构建 | 正常完成；没有虚构网址、canonical 或 sitemap；页面不索引 |
| 隔离的配置网址构建 | 用临时环境变量生成产物，检查 canonical、OG 与 sitemap 同源且只包含公开页；随后删除隔离产物 |
| HTML 抓取 | 不执行 JavaScript 也能读取首页正文；只有一个 H1；结构化数据可以解析且与正文一致 |
| 路由与响应 | 直接访问首页和所有已有功能路由、前进后退正常；未知路径为 404；个人页从初始响应就不索引 |
| 现有自动回归 | 运行现有前端测试与生产构建，按改动影响运行后端隔离测试；不加载真实服务配置进行付费或模型请求 |
| 浏览器回归 | 检查首页解析入口、表单校验、登录入口和导航，验证手机与桌面无新增横向溢出或脚本错误；下载与 AI 流程使用隔离接口验证前端行为 |

清理建议限定为本轮新建的测试脚本、模拟数据、临时服务、截图、临时报告及隔离构建产物。保留项目原有测试、既有报告、依赖、数据库、模型和正常构建能力；最终仅在维护文档中保留测试结论和人工验收步骤，不保留临时测试内容。清理前核对完整路径和本轮创建记录。

## 5. GEO 阶段设计

SEO 阶段通过并清理后，再整理 AI 能够直接引用的产品说明。内容以当前实现为依据，先回答用户问题，再给步骤和限制；不编造第三方背书、提升比例或实测结果。

建议新增可独立访问的公开使用说明 `/guide/`，并从首页和页脚提供正常链接。内容包含：产品是什么、如何下载视频、如何生成总结与导出字幕、无字幕怎么办、游客与登录能力区别、免费额度和平台限制。此页在无 JavaScript 时也能完整阅读。

| 内容 | 处理方式 |
| --- | --- |
| 简短答案 | 开头直接说明 SaveAny 的用途、登录要求和平台限制 |
| 操作步骤 | 解析 → 选择可用格式下载；游客不触发 AI；登录后先恢复已有结果，没有保存结果且额度可用时自动生成；使用转写字幕总结时需要单独点击 |
| 常见问题 | 根据现有实现回答字幕、转写、额度与恢复问题；结构化数据与可见回答一致 |
| 功能比较 | 比较游客、免费账号和 VIP 的真实功能，不虚构竞品数据 |
| 来源与日期 | 引用真实技术来源和已实施的产品规则，标注实际编辑日期，不每次构建伪造更新 |
| AI 搜索抓取 | 正式上线后允许 AI 搜索抓取公开页；不把训练用途爬虫与搜索引用混为一谈 |
| `llms.txt` | 可作为公开资料索引的补充；不把它当成所有 AI 都会读取的标准或排名保证 |

不发布站外文章、不联系第三方、不新增统计跟踪、不公开私人生成结果。Google 明确说明其 AI 搜索功能沿用 SEO 基础要求，不需要特殊 AI 标记，满足要求也不保证收录。参考：[Google AI 搜索与网站说明](https://developers.google.com/search/docs/appearance/ai-features)。
