# 万能视频下载网站 - 扩展功能本地运行指南

## 1. 运行环境

扩展功能与主项目使用同一套前后端。首次安装依赖、创建 JWT 密钥和启动基础服务，见[保姆级本地运行指南](./保姆级本地运行指南.md)；下文说明扩展功能需要的配置和操作。

| 工具 | 要求 | 用途 |
|------|------|------|
| Python | 3.11 或更新的兼容版本 | 运行 FastAPI 后端 |
| Node.js | 22.12+ | 安装前端依赖与运行 Vite |
| ffmpeg / ffprobe | 加入 PATH | 音视频合并、音轨转换与时长检查 |
| DeepSeek 配置 | 按需填写 | 总结、导图、问答和翻译 |
| faster-whisper + small 模型 | 按需安装 | 本地 CPU 语音转写 |
| Docker Engine / Desktop + Compose | 可选 | 容器方式启动 |
| Stripe 测试账号与 CLI | 可选 | 测试 Checkout 和付款回调 |

以下命令适用于 Windows PowerShell，除明确进入 `frontend` 外，均从项目根目录执行。

## 2. 环境变量

后端读取 `backend/.env`，已有配置可以继续使用。支付和转写按需启用，不影响游客解析与单条下载。

| 变量 | 默认值或要求 | 用途 |
|------|--------------|------|
| JWT_SECRET | 至少 32 字节的稳定随机值 | 登录 Token 签名 |
| DATABASE_PATH | backend/data/app.db | SQLite 数据文件，相对路径按项目根目录解析 |
| DOWNLOAD_DIR | backend/downloads | 单条下载与队列临时目录 |
| DEEPSEEK_API_KEY | AI 功能需要 | 模型调用密钥 |
| DEEPSEEK_BASE_URL / DEEPSEEK_MODEL | https://api.deepseek.com / deepseek-flash | 模型接口与型号 |
| CORS_ORIGINS | localhost 和 127.0.0.1 的 5173 来源 | HTTP 与 WebSocket 来源白名单 |
| ASR_ENABLED / ASR_MODEL_DIR / ASR_CPU_THREADS | false / backend/models/faster-whisper-small / 4 | 本地转写开关、模型目录和 CPU 线程 |
| PAYMENT_MODE / PAYMENT_LIVE_ENABLED | test / false | 使用测试支付，默认不启用正式收款 |
| STRIPE_SECRET_KEY / STRIPE_WEBHOOK_SECRET / STRIPE_PRICE_ID_VIP_30D | 有效测试密钥、回调签名和一次性 Price | Stripe 测试支付 |
| FRONTEND_URL | http://127.0.0.1:5173 | 支付回跳地址，Docker 覆盖为 8080 入口 |
| ALLOW_PROXY_FAKE_IP | false | 仅用于确认采用 Fake-IP 的本机代理 |

修改配置后重启后端。保持原有 JWT 密钥和数据库路径，不通过切换空库解决登录或升级问题。

## 3. 本地启动

后端从根目录启动，前端在另一个终端运行。后台任务采用单实例、单后端进程，不同时启动两份服务指向同一数据库和下载目录。

**后端：**

```powershell
.venv/Scripts/python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload --reload-dir backend
```

**前端：**

```powershell
cd frontend
npm.cmd run dev
```

| 地址 | 功能 |
|------|------|
| http://127.0.0.1:5173/ | 首页和单条下载 |
| http://127.0.0.1:5173/history | 本人下载与总结历史 |
| http://127.0.0.1:5173/queue | 后台任务、进度、取消和文件领取 |
| http://127.0.0.1:5173/billing | 会员权益和本人订单 |
| http://127.0.0.1:8000/api/health | 服务、ffmpeg 与模型配置状态 |
| http://127.0.0.1:8000/docs | 当前 API 结构 |

关闭页面不会取消后台任务，需要时在队列中显式取消；停止服务按 `Ctrl+C`。重启后排队项保留，执行中项标记中断，下载任务可手动重试。

需要更换本地端口时，在前端终端设置 `API_PROXY_TARGET`，并将实际前端来源加入后端 `CORS_ORIGINS`。下面示例要求后端已启动在 8001：

```powershell
$env:API_PROXY_TARGET = 'http://127.0.0.1:8001'
cd frontend
npm.cmd run dev -- --port 5174
```

## 4. Docker 部署

Docker 默认入口为 `127.0.0.1:8080`，后端只在 Compose 网络开放。数据库、临时下载文件和模型使用独立卷，默认不与 PowerShell 的本机库合并。

### 4.1 基础启动

先启动 Docker 并准备好 `backend/.env`，再构建和运行服务。基础镜像包含 ffmpeg，不包含转写依赖和模型。

```powershell
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail 100
```

浏览器打开 http://127.0.0.1:8080 。停止使用 `docker compose down`，保留数据卷；不要加 `-v`。本机 D 盘工具未加入 PATH 时，使用 `D:Dockerdocker.cmd` 替换 `docker`，启动入口为 `D:Docker启动Docker.cmd`。

### 4.2 可选转写

转写使用 ASR 覆盖文件，先安装可选依赖并显式准备模型。后续启动和停止使用同一组 `-f` 参数。

```powershell
docker compose -f compose.yaml -f compose.asr.yaml build
docker compose -f compose.yaml -f compose.asr.yaml run --rm --no-deps backend python -m backend.transcriber prepare-model
docker compose -f compose.yaml -f compose.asr.yaml up -d
```

### 4.3 容器代理

容器内的 `127.0.0.1` 指向容器自己。Docker Desktop 访问宿主代理时使用 `host.docker.internal` 和本机代理端口，按实际环境设置；`ALLOW_PROXY_FAKE_IP` 默认关闭，仅在核实代理 DNS 行为后开启。

## 5. 本地转写配置

PowerShell 方式需要单独安装转写依赖和模型。当前固定使用 small / CPU / int8，模型文件约 486 MB，首次准备需要联网。

```powershell
.venv/Scripts/python.exe -m pip install -r backend/requirements-asr.txt
.venv/Scripts/python.exe -m backend.transcriber prepare-model
```

在 `backend/.env` 设置 `ASR_ENABLED=true`，保留正确的 `ASR_MODEL_DIR`，重启后端。普通请求不自动下载模型，已有平台字幕时不运行转写；单条最多 30 分钟，完成后先显示字幕，再由用户决定是否总结。

免费/VIP 四项额度与成功结果恢复规则见[用户子系统方案](./【用户与AI额度子系统】方案设计文档.md)，翻译和转写流程见[扩展接口与数据方案](./【剩余扩展】接口与数据方案.md)。

## 6. Stripe 测试支付配置

套餐使用一次性 **CNY 990 分 / 30 天**的 Price，不自动续费。填写测试私钥、有效 Price ID 和回调签名后，通过 Stripe CLI 接收付款通知。

```powershell
stripe login
stripe listen --forward-to http://127.0.0.1:8000/api/billing/webhook
```

将监听输出的 `whsec_...` 填入 `STRIPE_WEBHOOK_SECRET`，重启后端并保持监听终端运行。Docker 入口改为 `http://127.0.0.1:8080/api/billing/webhook`；本机 CLI 未加入 PATH 时，用 `D:Stripestripe.cmd` 替换 `stripe`。

从 `/billing` 创建订单后跳转 Stripe 测试页面，付款后回到应用查询服务端确认结果。只有有效签名和匹配的已付款订单才能授予会员，重复通知不重复延长；缺配置时不开放购买，默认保持 `PAYMENT_MODE=test`、`PAYMENT_LIVE_ENABLED=false`。

## 7. 数据备份与迁移

后端启动时按版本升级数据库，升级前自动创建一致备份，保留最近 3 份自动备份。手动备份单独保存，不自动删除。

### 7.1 本机备份

备份使用当前配置指向的 SQLite 数据库，命令完成后打印实际路径。账号、用量和成功文本在重启后继续保留，不删除数据库来重新启动。

```powershell
.venv/Scripts/python.exe -m backend.migrations backup
```

手动文件保存在数据库同目录的 `backups/backup-manual-*.db`。恢复前停止所有访问该库的后端，另存当前库及其目录，不用旧备份覆盖运行中的数据库。

### 7.2 导入空容器卷

需要沿用本机账号和成功结果时，先停止本机后端并完成备份，再导入尚未初始化的容器卷。默认两个环境不自动合并，目标数据库已存在时停止导入，保留两份库。

将下面的备份文件名替换为上一条命令输出的路径，在完成 `docker compose build` 后运行：

```powershell
$backupPath = (Resolve-Path 'backend/data/backups/backup-manual-实际文件名.db').Path
docker compose run --rm --no-deps --user 0 --volume "${backupPath}:/import/app.db:ro" backend python -c "from pathlib import Path; import shutil,os; target=Path('/app/backend/data/app.db'); assert not target.exists(), '目标数据库已存在，停止导入并保留原库'; shutil.copyfile('/import/app.db', target); os.chown(target,10001,10001)"
docker compose up -d
```

导入后登录原账号，查看历史和额度；普通 `down / up -d` 保留数据，不删除卷来绕过已存在检查。
