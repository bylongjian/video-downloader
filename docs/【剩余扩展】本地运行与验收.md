# SaveAny 扩展功能：本地运行与验收

这份指南用于启动当前扩展版本，并检查历史、后台队列、字幕和会员入口是否正常。PowerShell 与 Docker 使用同一套代码；默认数据库各自独立，不会自动合并。本轮只按本地应用使用，不自动对外发布。

本指南对应分支 `feat/extensions-staged`。最终测试数量和真实联调结论以[总计划与阶段记录](./【剩余扩展】总计划与阶段记录.md)为准；不要把下面的操作步骤当成已经执行过的验收记录。

用户于2026-11-02确认Docker/Stripe两项验收通过，免做本次环境实测，不安装Docker或Stripe CLI，也不准备账号/配置。**这属于用户确认，技术事实仍是未执行真实容器构建运行、未执行Stripe Checkout，非实测通过。** 其他本地/隔离逻辑与浏览器自主验收已由主Agent实际完成，既有公开短样本继续作为证据；第6、7章仅为未来可选指南，不要求为本轮执行。

## 2. 配置哪些变量

配置只填写在当前项目自己的 `backend/.env`。保留已有 DeepSeek 兼容版本和模型配置；不要复制参考项目的配置，也不要把密钥发到聊天中。

| 变量 | 基础用法 |
| --- | --- |
| `JWT_SECRET` | 必填，至少 32 字节的本机随机值；保持稳定以继续识别现有会话 |
| `DATABASE_PATH` | 默认 `backend/data/app.db`；相对路径按项目根目录解析。不要通过换空库解决升级问题 |
| `DOWNLOAD_DIR` | 默认 `backend/downloads`；其中 `queue` 用于后台任务临时文件；启动前设置，修改后重启 |
| `CORS_ORIGINS` | 默认允许 `http://localhost:5173,http://127.0.0.1:5173`；WebSocket 同样检查这个白名单，填写实际浏览器来源 |
| `DEEPSEEK_API_KEY` | 可选；为空时 AI 生成不可用，失败不扣成功额度 |
| `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` | 沿用已有值，模板为 `https://api.deepseek.com` / `deepseek-flash` |
| `ASR_ENABLED` | 默认 `false`；准备依赖和模型后才改为 `true` |
| `ASR_MODEL_DIR` | 模型目录，模板为 `backend/models/faster-whisper-small`；PowerShell 从根目录启动，容器使用自己的绝对路径 |
| `ASR_CPU_THREADS` | 默认 `4`；仅影响本地 CPU 推理并行度，不改变每日额度 |
| `PAYMENT_MODE` | 默认 `test`；测试权益与正式环境分开计算 |
| `PAYMENT_LIVE_ENABLED` | 默认 `false`；本轮保持关闭，正式收款和真实资金操作仍需另行授权 |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` / `STRIPE_PRICE_ID_VIP_30D` | 测试支付配置，缺少时页面明确显示无法购买；不要填正式密钥代替测试账号 |
| `FRONTEND_URL` | PowerShell 默认为 `http://127.0.0.1:5173`，用于支付成功/取消回跳；Compose 覆盖为本机 8080 入口 |
| `ALLOW_PROXY_FAKE_IP` | 默认 `false`；仅确认本机代理把公网域名解析到 `198.18.0.0/15` 时开启，不能用于开放内网访问 |

当前 ASR 固定使用多语言 **small / CPU / int8**，不提供切换 GPU 或其他模型的界面。队列上限也是当前代码固定规则，不存在需要填写的 `TASK_*` 配置。

首次生成 JWT 密钥时运行下面命令，只把输出填到自己的 `.env`；已有密钥无需重置。

```powershell
.venv/Scripts/python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 3. 用 PowerShell 启动

后端在启动时检查配置、升级数据库并恢复持久任务。当前调度器按本地单实例、单后端进程设计，不要添加多个 Uvicorn worker，也不要同时运行两份后端指向同一个数据库和下载目录。

终端一，从项目根目录启动后端：

```powershell
.venv/Scripts/python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload --reload-dir backend
```

终端二，从根目录启动前端：

```powershell
Set-Location frontend
npm.cmd run dev
```

| 地址 | 应用于什么 |
| --- | --- |
| `http://127.0.0.1:5173/` | 首页与原单条下载工作台 |
| `http://127.0.0.1:5173/history` | 本人下载与总结历史 |
| `http://127.0.0.1:5173/queue` | 本人后台任务与实际下载进度 |
| `http://127.0.0.1:5173/billing` | 套餐、订单和服务端确认的会员状态 |
| `http://127.0.0.1:8000/api/health` | 服务、ffmpeg 和 AI 是否配置；不输出密钥 |
| `http://127.0.0.1:8000/docs` | 当前接口请求与响应结构 |

前端默认严格使用 5173；占用时先确认是不是自己已启动的服务。确实需要隔离样品时，可在单独终端设置后端代理并显式改端口，同时把该来源加入后端 `CORS_ORIGINS`：

```powershell
$env:API_PROXY_TARGET = 'http://127.0.0.1:8001'
Set-Location frontend
npm.cmd run dev -- --port 5174
```

停止时在各自终端按 `Ctrl+C`。修改 `.env` 后重启后端。关闭队列页面不会取消后台任务；重启后排队项继续等待，原来执行中的项标记中断，用户决定是否重试。

## 4. 按需启用本地语音转写

转写会先检查平台字幕，已有字幕就不运行语音模型。没有字幕时，用户显式发起任务，后端下载音轨、检查真实时长，再在本机推理；完成后先交付字幕，是否生成总结由用户另行决定。

从根目录安装可选依赖，并检查 `.env` 中的模型目录，然后执行唯一会主动下载模型的准备命令：

```powershell
.venv/Scripts/python.exe -m pip install -r backend/requirements-asr.txt
.venv/Scripts/python.exe -m backend.transcriber prepare-model
```

准备完成后设置 `ASR_ENABLED=true`，重启后端。模型文件留在 `ASR_MODEL_DIR`，不会在普通转写请求中自动下载。缺依赖、缺模型或没有 ffmpeg/ffprobe 时，任务明确失败且不扣转写额度。

当前 `small` 来自 faster-whisper 对应的公开 Hugging Face 模型仓库；本轮实际准备文件约 **486,215,847 字节**，另需安装依赖及临时音频空间。公开11秒英文语音在独立隔离库首测25.95秒，真实HTTP闭环38.45秒，均包含音轨获取/转换/本地识别；这不是长视频速度保证，噪音、机器性能和网络会影响效果。

| 规则 | 免费账号 | VIP |
| --- | --- | --- |
| 每日总结 | 3 次 | 30 次 |
| 每日问答 | 10 次 | 100 次 |
| 每日翻译 | 3 次 | 20 次 |
| 每日转写 | 60 分钟 | 240 分钟 |
| 单条转写时长 | 最多 30 分钟 | 最多 30 分钟 |

四项额度相互独立，服务端北京时间零点换日；跨日任务归属预占日期。转写按实际音轨秒数向上取整结算，完整成功才计量，失败/完成前取消释放预占。同账号相同来源已有成功结果免费恢复，主动重新生成成功才再计量。翻译单次最多 20000 原文字、1000 段，目标语言为简体中文、英文、日文；超过限制明确拒绝，不悄悄截断。

## 5. 数据如何升级与备份

升级会保留账号、会话、原额度和成功总结，再增加历史、任务、译文、转写与付款表。启动前自动创建 SQLite 一致备份，各版本在事务内升级并检查完整性；失败会停止启动，不通过删除数据库重新开始。

需要手动备份时从根目录执行：

```powershell
.venv/Scripts/python.exe -m backend.migrations backup
```

命令读取当前 `.env` 指向的库，通过 SQLite Backup API 写入同目录的 `backups/backup-manual-*.db`，并打印实际备份路径。自动升级备份最多保留最近 3 份，手动备份不自动删除；不要把运行中的 `app.db` 单独复制并忽略 WAL 文件。

| 数据 | 保存和删除影响 |
| --- | --- |
| 账号、额度、成功总结 | 重启不清空；总结直接复用原结果表，长期保留至本人删除；删除总结同时移除对应免费恢复内容和关联译文，不返还成功额度 |
| 下载历史 | 登录后才记录链接、元信息与状态；不追记游客下载，不保存 CDN 直链、卡号或密钥；删除不删除用户电脑上的文件 |
| 后台媒体 | 准备完成后保留 24 小时供本人重复领取；过期需重新下载；失败/取消清理，正在写入或发送的文件先等待释放 |
| 任务快照 | 终态保存 30 天；快照过期不删除已成功的文本结果或下载历史 |
| 转写和译文 | 成功文本长期保存并免费恢复；删除转写同时删除依赖它的译文，已经保存的成功总结保留自己的正文与字幕 |
| 问答与付款 | 问答正文不持久保存；订单、最少支付事件和权益长期保留，不保存完整回调、付款卡或账单地址 |

删除来源时若仍有相关任务，先取消任务再删除。恢复备份前停止所有指向该库的后端，并另存当前库及其目录；不要用旧备份覆盖正在写入的数据库，也不要降级程序读取更高版本的库。

## 6. 可选参考：用 Docker 在本机启动

本轮用户确认Docker验收通过并免本次环境实测，不安装、不执行以下命令，技术事实非容器实测通过。将来如果选择容器方式，默认只映射`127.0.0.1:8080`，后端仅在Compose网络内开放；镜像不包含本机`.env`、数据库、模型和缓存，账号与临时文件分别保存到命名卷。

先安装并启动 Docker Engine/Desktop，确认 `docker version` 与 `docker compose version` 可用，再在根目录执行：

```powershell
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail 100
```

打开 `http://127.0.0.1:8080`。后端健康检查要求 ffmpeg 可用，前端等后端健康后启动。基础镜像没有 ASR 可选依赖和模型，普通解析、下载、历史及已配置的 DeepSeek 功能不受影响。

需要转写时使用同一组覆盖文件启动，模型在独立 `models` 卷；先显式准备模型，再启动服务：

```powershell
docker compose -f compose.yaml -f compose.asr.yaml build
docker compose -f compose.yaml -f compose.asr.yaml run --rm --no-deps backend python -m backend.transcriber prepare-model
docker compose -f compose.yaml -f compose.asr.yaml up -d
docker compose -f compose.yaml -f compose.asr.yaml ps
```

停止基础服务使用 `docker compose down`；ASR 组合使用同样的两个 `-f` 参数执行 `down`。普通 `down` 保留卷；不要添加 `-v`，它会删除卷中的账号、额度、文本和模型。重建镜像也不需要清空数据。

### 6.1 可选：把本机库导入一个空容器卷

默认容器卷是独立新库。只有希望沿用 PowerShell 的账号和成功结果时才执行导入；先停止本机后端，再运行前面的手动备份命令，保留原库和备份。下例要求容器数据库卷尚未初始化，目标已存在就会拒绝覆盖。

先完成 `docker compose build`，将下面的备份文件名替换为命令实际打印的路径，再在根目录执行。不要同时启动容器后端写库。

```powershell
$backupPath = (Resolve-Path 'backend/data/backups/backup-manual-实际文件名.db').Path
docker compose run --rm --no-deps --user 0 --volume "${backupPath}:/import/app.db:ro" backend python -c "from pathlib import Path; import shutil,os; target=Path('/app/backend/data/app.db'); assert not target.exists(), '目标数据库已存在，停止导入并保留原库'; shutil.copyfile('/import/app.db', target); os.chown(target,10001,10001)"
docker compose up -d
```

导入后登录原账号，检查历史内容与当日额度，再 `down` / `up -d` 检查仍能恢复。若目标已存在，不删除卷来绕过检查；保留两份库，先确定需要哪一份，当前不支持自动合并。

### 6.2 容器网络与本机代理

容器中的 `127.0.0.1` 是容器自己。Docker Desktop 访问宿主代理通常使用 `host.docker.internal` 加代理端口，具体需按本机代理设置验证；不要直接照搬 Windows 环境的回环代理地址。`ALLOW_PROXY_FAKE_IP` 仍默认关闭，仅在核实代理 DNS 行为后启用。当前尚未进行容器代理实测。

## 8. 本地人工验收表

先跑无费用的下载、历史和恢复，再做已授权的小样。使用自己有权处理的公开内容；失败时记录输入、步骤和提示，不发送密钥。下面明确区分真实功能与测试边界。

| 操作 | 应看到的结果 |
| --- | --- |
| 游客解析并下载一条可访问的视频 | 原单条下载可用，不要求登录或购买；不创建个人历史 |
| 登录后下载，再打开“我的历史” | 显示链接、标题/格式与实际交接状态，不声称已写入浏览器磁盘 |
| 从历史打开已保存总结，刷新、退出重登后再打开 | 恢复同一份字幕、摘要、导图，不调用模型、不扣总结次数；原平台不可用也能阅读和导出 |
| 换另一个账号后打开历史/队列 | 不出现前一账号内容；别人或不存在的记录都不可访问 |
| 删除一条总结 | 提示免费恢复内容与关联译文会移除、不返额度；确认后列表与详情更新 |
| 批量输入重复链接、一条有效链接和一条失效链接 | 同批相同 URL+格式去重；有效项与失败项互不影响，每项可见真实状态 |
| 下载中观察进度，断网后恢复或刷新页面 | WS 显示实际字节/速度；未知总量不造百分比，合并只显示阶段；重连先取最新快照，WS 不可用回退轮询 |
| 显式取消排队/执行任务，再手动重试 | 排队项取消；执行项先显示正在取消、到边界停止，取消后不能成功结算；重试生成关联的新任务 |
| 领取准备好的文件，刷新后再次领取 | 24 小时内本人可重复下载；服务端准备完成与浏览器交接是两种状态，过期需重新下载 |
