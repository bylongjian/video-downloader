## 2. 验什么，哪些数据是模拟的

容器内数据库、HTTP 与文件响应要实际运行，Stripe 要接触真实的测试环境。为了避免重复付费，持久化测试可以写入明确标记的模拟文本，但保存、读取、重启恢复必须经过真实数据库事务和接口，不能把模拟正文说成此次重新调用模型的结果。

| 检查内容 | 必须真实执行 | 允许的模拟边界 |
| --- | --- | --- |
| Docker 构建与启动 | 当前项目镜像构建、容器健康、Nginx 到 API 的请求 | 无，不能用 `hello-world` 或静态配置审查替代 |
| 游客下载 | 真实公开视频解析、文件下载与必要的文件检查 | 平台不稳定时如实记录失败，不填示例文件充成功 |
| 账号与持久化 | 独立测试库注册/登录、真实事务保存、HTTP 恢复、容器停止重启后再读 | 总结正文可用带“模拟文本”标记的小样，不调用 DeepSeek；不复制真实业务库 |
| 下载状态/进度 | 实际后台任务、API/WS 连接和服务端状态 | 隔离错误用例仅证明对应错误处理，单独注明 |
| Stripe Checkout | 有效测试账号下真实商品/Price、Checkout、支付商确认及项目权益读取 | 只用官方测试付款方式，不使用真实卡和真实扣款 |
| 支付验签与重复处理 | 真正签名回调、真实本地订单和权益事务 | 回放同一条测试事件可用于检查重复处理，但不冒充新的实际付款 |
