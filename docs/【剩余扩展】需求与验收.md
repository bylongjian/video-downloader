# SaveAny 剩余扩展：需求与验收

这轮要让用户找回已处理的视频、一次安排多个下载，并在需要时翻译或转写字幕，最后接入付费会员。已有账号、额度、总结恢复及下载能力继续使用，不能为了扩展重做一套。

总计划已获用户确认并实施。2026-11-02，用户要求主 Agent 自行验收，并明确 Docker、Stripe 两项默认验收通过、无需准备对应工具；这两项采用“用户确认通过、免本次环境实测”，保留未实际运行的技术事实，不再作为本轮交付阻塞。本地自主验证见[自主验收记录](./【剩余扩展】自主验收记录.md)，配套为[接口与数据方案](./【剩余扩展】接口与数据方案.md)、[总计划与阶段记录](./【剩余扩展】总计划与阶段记录.md)。已验收账号规则仍以原子系统文档及实际代码为准。

## 1. 需求小卡与现状

用户应能从个人历史免费打开保存结果，把多个下载放入队列，看到可信的处理进度，并按明确的额度使用新增 AI 能力。本轮先确认业务范围，再按七个可演示阶段实施；不提交、合并、推送或发布。

| 项目 | 本轮约定或建议 |
| --- | --- |
| 主流程 | Superpowers：只读核查 → 总计划确认 → 多 Agent 按公共接口分工 → TDD、集成和独立审查 → 样品反馈 → 最终验收 |
| 开发基线 | `main` 的 `ff8d07f`，创建分支 `feat/extensions-staged`；开始时没有未提交改动 |
| 工作目录 | 当前项目；`../free-video-downloader` 仅阅读源码与模板，禁止读写真实配置、密钥和数据库 |
| 当前已实现 | 游客解析/直链与代理下载、邮箱账号与真实退出、北京时间每日 3 次总结/10 次问答、并发预占与成功计次、成功结果免费恢复、四个 AI 标签、字幕/导图导出 |
| 当前未实现 | 个人历史列表、Docker、批量队列、WS 下载进度、逐段字幕翻译、语音转写、VIP 订单和支付 |
| 首个样品 | 登录 → 我的历史 → 打开已保存总结 → 原视频临时不可访问也能阅读及导出 → 退出后清空个人内容 |
| 主要待确认 | 保存与删除规则、翻译/转写提供商与独立额度、会员价格与权益、支付测试配置 |

最重要的五项预期是：已有能力不退步；历史打开不重复扣次；任务失败互不影响且进度不造假；新增能力各用各的额度；会员只依据服务端确认的付款授予。

## 2. 必须保留的行为

这些是本轮的回归底线，不是重新讨论的功能。新增接口、页面及数据库升级都必须通过同一组核心场景。

| 编号 | 必须保留 |
| --- | --- |
| B1 | 游客可以解析和单条下载；新增个人历史、批量任务与 AI 要求登录，不给原单条下载加登录或购买门槛 |
| B2 | 免费总结每天 3 次、问答每天 10 次，独立计算；服务端北京时间零点换日，跨日请求归属预占日期 |
| B3 | 完整成功才结算；失败、完成前取消和过期释放预占，并发不超用；服务端成功后丢失最后响应不回滚成功 |
| B4 | 同账号、同原始 URL、同总结语言已有成功结果免费恢复；退出重登、刷新及重启不再次生成 |
| B5 | 主动重新总结成功才再计一次并替换结果；失败保留上次成功结果；保存与结算同一事务 |
| B6 | 账号之间隔离；退出/换号使旧响应失效并清空旧内容；已撤销会话不能继续访问 |
| B7 | 字幕 SRT/VTT/TXT、导图 SVG/PNG、连续问答及现有取消功能继续可用；问答正文仍不持久保存 |
| B8 | 模型分析仍以现有前 15000 字符为限，保留提示；新翻译限制不被误当成总结覆盖全文 |

## 3. S1：下载与总结历史

历史解决“上次处理过什么、如何重新打开”的问题，不建设服务器视频收藏库。总结列表直接查询现有 `summary_results`，只保留每个账号、原始链接、总结语言的最新成功结果。

| 范围 | 完成标准 |
| --- | --- |
| 归属与入口 | 登录后页头/手机入口可打开“我的历史”，分下载与总结；游客可下载但不保存个人历史，也不登录后补记游客行为 |
| 下载记录 | 保存原始链接、标题/平台（有则显示）、格式、时间和处理状态，不保存 CDN 直链、Cookie、真实文件路径；连续下载可有多条记录 |
| 状态含义 | 区分“已发起”“已交给浏览器”“服务端文件已准备”“失败”“已取消”“文件已过期”“处理中断”；没有任何状态声称浏览器磁盘已保存 |
| 总结记录 | 复用已保存字幕、摘要、导图；为旧记录补稳定 ID，缺标题显示“未记录标题”，不访问视频平台补齐、不再次调用模型 |
| 打开与刷新 | 历史详情直接读数据库，不依赖视频重新解析；原视频失效也可阅读、复制、导出。需要再下载时由用户显式点击重新解析 |
| 分页 | 每页 20 条，按最近处理时间排序；支持切换两类，不做全文搜索、文件夹、标签或版本库 |
| 删除 | 单条删除本人记录，弹窗说明后果；删除总结会同时移除该份免费恢复内容及关联译文，不返还已成功使用额度；下载历史删除不删除用户电脑文件 |
| 失败 | 无记录是空列表；数据库故障是可重试错误，不能当成无结果启动生成；历史写入失败不阻断原视频下载，页面提示这次未能保存历史 |

建议长期保留账号与成功文本结果，直到本人明确删除；下载历史也保留至本人删除。旧版本下载没有保存过，不能补回。旧成功总结直接出现在列表中，不复制一份正文。

## 4. S2：Docker 本地容器化

Docker 用来固定本地运行环境，让另一台电脑按说明启动同一项目。本轮只开放本机入口，不部署公网，联网仅用于下载镜像、视频、模型和访问已确认的 AI 服务。

| 范围 | 完成标准 |
| --- | --- |
| 结构 | 前端静态构建 + Nginx；后端 Python 3.11 + ffmpeg/ffprobe + 单 Uvicorn worker；不引入 Redis/Celery/PostgreSQL |
| 地址 | 宿主入口建议 `http://127.0.0.1:8080`；后端只在 Compose 网络提供服务；保留原 PowerShell 双进程启动 |
| 数据 | SQLite 整个目录使用独立持久卷，下载临时文件另用卷；停止/重建容器保留账号、额度和成功结果 |
| 原有本机库 | 默认新卷是独立环境，不默默替代本机数据库；提供停写、备份、导入卷与验证的操作，保留原文件，不自动合并两个库 |
| 配置 | 真实 `.env`、数据库、下载缓存和虚拟环境不进入构建上下文；只从当前项目本机配置注入。容器不能使用 Windows 的数据库绝对路径 |
| 代理与 AI | Nginx 正确代理 API/SSE，后续接 WS；记录容器访问宿主代理方式，Fake-IP 默认关闭；没有 AI 密钥不影响游客下载 |
| 验收 | 构建、健康检查、游客下载、登录/结果恢复、停止重启后数据保留；实际运行前必须有 Docker Engine/Desktop |

当前终端未找到 `docker` 命令，因此尚无容器构建或运行结果。补齐环境前可以完成配置、代码审查和非容器测试，但该阶段只能标“容器实测受阻”，不能按真实通过交付。

## 5. S3：批量下载与任务队列

批量功能让用户一次安排几条独立视频链接，失败项不拖垮整批。首版只处理显式给出的单视频链接，不递归展开播放列表、频道或整站内容。

| 范围 | 完成标准 |
| --- | --- |
| 输入 | 登录后每行一条 URL，每批最多 10 条；去首尾空白后完全相同 URL + format_id 在同批去重，返回去重数；不同批允许再次下载 |
| 格式 | 首版整批共用 `format_id`，默认沿用 `bestvideo+bestaudio/best`；不在批量表单逐条预解析画质 |
| 队列 | SQLite 保存任务；服务全局最多 2 个同时下载，同账号最多 2 个下载；同账号未完成任务最多 30 个，全局最多 100 个，达到上限明确提示稍后再试 |
| 状态 | 排队 → 解析/下载/合并 → 服务端文件准备完成，或失败/取消；初期轮询展示真实状态，不做假百分比 |
| 持续执行 | 关面板、导航或断网不取消持久任务；用户显式取消才请求后台停止；退出后不再读个人任务，但已接收任务按原账号继续执行 |
| 取消 | 排队立即取消；运行中先“正在取消”，在下载/模型阶段边界协作停止并清理。阻塞网络或 ffmpeg 合并期间可能需要等待，不承诺立即终止外部进程；取消标记落库后禁止再变成成功 |
| 重试/重启 | 失败或取消可手动重试，生成新任务并关联旧任务；不自动反复请求平台。重启保留排队项；执行中项标记中断并释放资源，用户决定是否重试 |
| 文件领取 | 准备好的文件保留 24 小时，过期返回 410 并提示重新下载；本人可重复领取，无 ZIP 打包；浏览器接收与服务器准备分开展示 |
| 磁盘 | 队列单文件最多 2 GiB、临时文件合计预算 10 GiB；已知长度提前拒绝，下载中按实际写入监控，未知长度同样不能无限写；不把此限制加给已有单条下载 |
| 记录 | 每个下载任务关联一条下载历史；任务状态由后端更新，不额外复制总结结果 |

用户在实施审查后确认：本轮批量路径仅支持可以持续监控字节的 HTTP、原生 HLS/DASH；外部 ffmpeg 下载路径明确提示改用原单条下载，保留单条原有行为。下载失败/取消/中断可在队列重试；字幕任务回到原视频字幕入口重新选择来源和语言提交，避免把旧设置猜错。

技术上先限定本地单实例、单进程。程序对临时目录的清理必须排除活跃下载、正在发送的文件和数据库；失败、取消文件及时清理，成功文件从准备完成起计 24 小时。短时重试或系统缓存可能占额外空间，运行指南应说明预算不是对整台电脑的硬盘配额。

## 6. S4：WebSocket 真实下载进度

进度来自下载器实际收到的字节和正在做的处理阶段。浏览器断线不能丢掉任务，也不能凭定时器把进度推到成功。

| 范围 | 完成标准 |
| --- | --- |
| 数据 | 推送任务 ID、递增版本、阶段、下载字节、已知/估计总量、速度与预计剩余时间；未知字段为 null |
| 百分比 | 只对有依据的字节总量显示该下载阶段百分比，估计总量明确标“估计”；分离音视频按分轨展示，不将某一轨 100% 当整项完成 |
| 合并 | 合并/后处理只显示阶段；下载结束与最终文件可领取分开，不给 ffmpeg 伪造进度 |
| 权限 | 连接时检查 Token 与会话、任务归属和 Origin；不把 72 小时 Bearer 放进 URL；退出或会话过期关闭个人订阅 |
| 重连 | 重连先 GET 最新任务快照，再订阅并按版本忽略旧包；WS 不可用则退回轮询；断线不报下载失败或成功 |
| 覆盖 | 批量队列和用户显式选择的“后台下载”可见真实进度；现有浏览器直链单下载保留阶段文字，服务器观察不到的网络不伪造百分比 |

本阶段不替换总结与问答的 SSE，不建设多进程广播服务。真实平台缺少总长度时，只显示“已下载多少”和阶段就算正确行为。

## 7. S5：字幕翻译

翻译针对字幕逐段产生译文，而不是只改变总结语言。首版从本人已保存成功总结的字幕，或下一阶段完成的本人转写字幕开始；原字幕始终保留，译文与其分开保存。

| 范围 | 完成标准 |
| --- | --- |
| 服务 | 建议复用当前 DeepSeek 配置与 OpenAI 兼容 SDK，不引入第二家翻译服务；实际调用有提供商费用，确认计划前不发请求 |
| 语言与长度 | 首版目标简体中文 `zh`、英语 `en`、日语 `ja`；每次完整原文最多 20000 字符、1000 段，超出明确拒绝，不默默截断翻译 |
| 执行 | 用户显式选择目标语言并提交；后台任务可取消，按段分批、固定段 ID 连接结果；第三方返回必须完整匹配段 ID，时间戳由服务器沿用原值 |
| 展示/导出 | 字幕标签切换原文/译文，译文复用 SRT/VTT/TXT 导出；不做双语烧录、配音或字幕嵌入视频 |
| 保存 | 按账号、字幕来源 ID、原文 hash、目标语言保存成功译文；相同来源版本成功结果免费恢复，来源变化不误用旧译文 |
| 失败 | 任一批失败、缺段、空结果、截断或取消，整个翻译不成功、不覆盖上一成功版本、释放预占；原字幕仍可用，不自动重试产生额外费用 |
| 当前边界 | 不新增独立的游客字幕获取/翻译接口；没有保存字幕的失败总结，需先成功保存总结或完成转写后再翻译；不挤占总结或问答额度 |

建议免费独立 **3 次/日**，VIP 独立 **20 次/日**，同样按服务端北京时间。完整成功计 1 次；请求同源同语言并发合并为同一任务，不能同时重复调用模型。用户明确“重新翻译”成功才另计一次，失败保留旧译文。

## 8. S6：无字幕视频转写

没有平台字幕时提供显式的“语音转写”，用户知道这一步需要下载音频和运行模型。转写成功先交付可阅读、可导出的字幕，用户再决定是否花总结额度生成摘要。

| 范围 | 完成标准 |
| --- | --- |
| 服务 | 建议本地 `faster-whisper`，多语言 `small`、CPU `int8`，单转写并发；没有云端上传或按分钟 API 账单，但占用本机 CPU、内存、磁盘和模型下载流量 |
| 模型 | 依赖和模型不混进基础镜像；可选 ASR 依赖/Compose profile，模型缓存单独卷。首次显式准备模型后请求才运行；缺模型清楚提示，不在普通页面请求中偷偷下载 |
| 输入限制 | 按用户反馈，免费与 VIP 单视频均最多 **30 分钟**；不支持直播、播放列表、用户上传音频、说话人分离、GPU 调优 |
| 检查 | 先检查平台字幕；已有可用字幕返回说明并停止，不运行 ASR、不占转写额度；时长未知先获取并检查音频实际时长，超过限制不转写 |
| 音频 | 复用下载封装取音轨，ffmpeg 转为模型可读音频；只保留本次临时音频，完成/失败/取消清理；转写任务下载部分也受空间预算控制 |
| 输出 | 沿用 `has_subtitle/language/source/segments/full_text` 字幕结构，明确 `source=transcription`；中英文优先验证，不保证所有语言、噪音和专有名词准确 |
| 总结/翻译 | 同账号同链接成功转写免费恢复；仅本人完成的转写 ID 可供总结、翻译；转写不自动生成总结，不在无字幕的旧总结接口内自动回退到收费步骤 |
| 失败 | 无音轨、无语音、超时、模型不可用和取消不计额度，不产生假字幕，不覆盖旧成功字幕；执行中取消在分段边界响应，暂时阻塞显示“正在取消” |

按用户反馈，免费独立 **60 分钟/日**，VIP **240 分钟/日**。内部以 `ceil(实际音频秒数)` 预占和结算，不按分钟进位，界面显示分钟/秒。音频时长检查通过、开始 ASR 前预占；排队不占用，跨日按预占时日期，失败释放。单任务最长 30 分钟执行预算，超时后不允许成功结算；输入时长上限不代表本机能在同样时长内完成，真实速度另测。

模型准备拟允许下载一个公开 small 模型，下载前报告实际来源和预计容量；如需额外付费、改为云服务、下载量超过 1 GiB 或引入 GPU 环境，另行确认。离线推理需要模型文件已在本机；下载模型本身仍需网络。

## 9. S7：VIP 与支付

会员提高已明确能力的使用额度，付款状态和权益都以服务端为准。建议先接 Stripe 测试环境的真实 Checkout 与签名回调；“测试环境闭环”和“真实资金支付已验证”是两项不同结果。

| 项目 | 建议范围（待用户确认） |
| --- | --- |
| 提供商 | Stripe Checkout；需要用户自己的可用测试账号，商户资格/地区和可用币种由账号确认，不假定大陆个人账号一定能开通 |
| 商品 | 一次购买 30×24 小时，不自动续费；测试金额暂按页面规划的 CNY 990 分，最终币种/金额需和 Stripe Price 一致 |
| 权益 | 总结 30 次/日、问答 100 次/日、翻译 20 次/日、转写 **240 分钟/日**，转写单条最多 **30 分钟**；下载能力不变，无“无限调用”承诺 |
| 免费不退步 | 仍是总结 3、问答 10，新增免费翻译 3、转写 **60 分钟/日**；批量 10 条和相同队列限制向登录免费用户开放，不借机限制原能力 |
| 续购 | 从 `max(当前有效到期时间, 付款确认时间)` 增加 30 天；不同订单各生效一次，同一订单重复事件不再次延长 |
| 生效 | 只有验签、环境/订单/金额/币种/商品匹配且确实已支付后，在一笔事务记成功并写权益；前端回跳只显示“确认中”，不凭参数开通 |
| 未成功 | 创建失败、未付款、Checkout 过期不授予权益；用户关闭/返回不等于服务端付款取消，允许后来有效的成功回调正确结算 |
| 到期 | 按服务端时间恢复免费上限，当天已有用量不清零，剩余不小于 0；已合法预占任务保留原授权并按规则完成，恢复结果永远不收费 |
| 退款 | 首版不提供应用内退款申请；支付后台全额退款/争议撤销该订单权益，按其余有效订单重新计算合并到期时间，不撤销其他订单但合并到期可能改变；部分退款进入明确的人工处理状态，不承诺自动折算天数 |
| 正式环境 | 实现相同验签与订单路径，默认测试模式；正式密钥、真实商户收款、真实扣款、退款执行和公网发布需另行明确授权及准备；本轮不执行 |

原套餐页的 ¥9.9 与“无限总结”只是规划，不能当成已确认商业权益。当前建议改为上表明确额度；如果用户希望保留无限或更换支付提供商，先调整本章、接口方案和测试标准再开发。

## 10. 数据保存与统一错误要求

文本恢复与临时媒体是两种数据：前者用于用户再次阅读，后者只是让浏览器领取下载。删除、失败和超时都要说明影响范围，不拿清空数据库解决升级或运行问题。

| 数据 | 保存建议与删除影响 |
| --- | --- |
| 账号/会话/原两项额度 | 保留当前规则；本轮不做删除账号、找回密码、验证码或变更旧账本保存政策 |
| 成功总结 | 仍唯一来源 `summary_results`；最新成功正文、字幕、导图长期保留至本人删除；重新生成不保存所有历史版本 |
| 下载历史 | 长期保留链接/元信息/状态，不含媒体文件或 CDN 直链；本人可单条删除 |
| 队列任务 | 排队/执行状态持久化；终态任务快照保存 30 天自动清理，下载历史保留；不因快照到期删除成功字幕/译文或额度记录 |
| 媒体/音频 | 原单条下载仍响应结束清理；队列媒体准备完成后 24 小时；ASR 音频用完即清理；清理不碰用户本地文件 |
| 译文/转写 | 本人成功结果长期保存、免费恢复；可删除转写或译文，删除转写同时删除依赖它的译文；已经保存的成功总结仍有自己的完整内容，不连带丢失 |
| 新增额度账本 | 保存请求 ID、种类、用量单位、预占日期、状态与时间，不保存模型密钥、问答正文或付款卡信息 |
| 订单/支付事件/权益 | 为付款追踪长期保存最少字段，不随历史删除；不存完整回调包、卡号、账单地址或真实支付配置 |

所有受保护的 ID 读取/删除/取消都必须加本人归属检查，其他账号的 ID 与不存在统一返回 404。401、429、503 使用可判断错误码；已开始任务的错误写入任务状态，不伪装成成功。仅在 HTTP/用户输入/第三方响应边界校验，内部意外错误直接暴露给日志和测试。

## 11. 阶段验收和总计划确认

每阶段运行精简核心测试并给可以操作的样品，自动测试隔离模型、支付和视频平台。样品说明真实接口、模拟边界以及用户尚未体验的部分；关键页面反馈后才大幅展开依赖它的界面。

| 阶段 | 操作 | 应看到的结果 |
| --- | --- | --- |
| S1 | 登录 A 打开历史，原视频故障时重开总结，再换 B | A 的保存结果可离线于平台阅读/导出，无 POST 总结、无扣次；B 看不到 A 内容；删除后果清楚 |
| S2 | 本地 Compose 启动，注册/总结，再停止重建 | 入口可用，原账号/用量/成功结果保留，真实密钥不在镜像内；无 Docker 则如实记录阻塞 |
| S3 | 提交成功/重复/失败链接，取消、重试并重启 | 同批去重、单项失败隔离、并发有上限、重启能恢复状态；有效文件可领取，过期明确提示 |
| S4 | 下载时断开 WS，再重连；查看未知长度案例 | 已下载量来自 hook；重连得到最新快照，未知总量不出现编造百分比；不能订阅他人任务 |
| S5 | 翻译已有字幕，导出，再让模型一批失败 | 时间戳相同、目标语言正确、成功只扣翻译一次；失败不覆盖旧译文、不影响 3/10 |
| S6 | 无字幕短片转写、导出，再手动总结；换有字幕视频 | 本地真实 ASR 出字幕，按秒结算；手动总结另扣总结一次；有字幕不启动 ASR；取消/超限不扣转写 |
| S7 | 测试 Checkout → 回跳 → 签名回调 → 重复回调 → 到期/退款测试 | 只有匹配的已支付订单开通一次；回跳参数不能伪造，测试权益标识清楚；没有真实资金扣款 |

待确认事项集中在第 3、7、8、9、10 章。用户确认整份总计划后，主 Agent 连续推进已确认范围，不逐个内部小任务重复求准；新增范围、关键变化、样品反馈和外部费用仍保留确认点。若缺 Docker 或支付配置，先完成独立可验证部分，实际联调项保持受阻状态，不能把测试替代品当最终完成。
