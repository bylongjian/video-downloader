# 万能视频下载网站 - 方案设计文档

## 1. 技术架构

项目采用 Vue 3 前端和 FastAPI 后端，下载、AI 与个人数据按模块处理。SQLite 保存账号、额度和成功结果，后台任务通过同一数据库恢复状态。

```
用户浏览器
    ├─ 首页 / 视频工作台
    ├─ 摘要 / 字幕 / 导图 / 问答
    └─ 个人历史 / 后台队列 / 会员订单
                │ HTTP / SSE / WebSocket
FastAPI 后端
    ├─ 视频处理    → yt-dlp / 抖音解析 / ffmpeg
    ├─ AI 处理     → 字幕提取 / DeepSeek
    ├─ 字幕任务    → 翻译 / 本地 faster-whisper
    ├─ 账号与额度  → JWT / 会话 / 预占与结算
    └─ 会员支付    → Stripe Checkout / 签名回调
                │
              SQLite
```

本地开发使用 Vite 代理，Docker 使用 Nginx 提供静态页面并代理 API / SSE / WebSocket。首页与公开指南在构建时预渲染，个人内容通过认证接口读取。

## 2. 技术栈选型

技术选型围绕视频处理、AI 内容展示和本地部署展开，转写与支付按需配置。

| 层次 | 技术 | 选型理由 |
|------|------|----------|
| 前端框架 | Vue 3 + Vite | 页面组件化，开发与构建轻量 |
| 页面样式 | Tailwind CSS | 统一布局、排版和响应式样式 |
| Markdown | marked + DOMPurify + typography | 解析并清理 HTML，展示摘要和回答 |
| 思维导图 | markmap-lib + markmap-view | Markdown 转交互 SVG，支持完整导出 |
| 后端接口 | FastAPI | JSON、SSE 和 WebSocket 共用后端 |
| 视频处理 | yt-dlp + ffmpeg / ffprobe | 平台解析、音视频合并与音轨检查 |
| AI 模型 | DeepSeek，默认 deepseek-flash | 通过 OpenAI 兼容 SDK 调用 |
| 数据与认证 | SQLite + bcrypt + PyJWT | 本地保存数据，密码哈希与会话认证 |
| 语音转写 | faster-whisper small / CPU int8 | 可选本地模型推理 |
| 支付 | Stripe Checkout | 托管付款，服务端回调确认权益 |
| 部署 | Docker Compose + Nginx | 固定环境，统一代理与持久化 |

## 3. API 设计

核心接口负责视频解析、下载和 AI 输出，个人功能接口使用 Bearer 认证。JSON 统一返回 `success / data`，业务失败返回 `code / error`；AI 生成使用 SSE。

### 3.1 解析视频信息

解析接口返回源视频元信息和可用格式，供页面展示与下载选择。

```
POST /api/parse
Content-Type: application/json

Request:
{
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
}

Response (200):
{
    "success": true,
    "data": {
        "id": "dQw4w9WgXcQ",
        "title": "视频标题",
        "thumbnail": "https://i.ytimg.com/vi/xxx/maxresdefault.jpg",
        "duration": 212,
        "duration_string": "3:32",
        "uploader": "上传者名称",
        "platform": "YouTube",
        "view_count": 1500000,
        "upload_date": "20240101",
        "formats": [
            {
                "format_id": "137+140",
                "ext": "mp4",
                "resolution": "1920x1080",
                "height": 1080,
                "filesize": null,
                "filesize_approx": null,
                "vcodec": "avc1",
                "acodec": "merged",
                "has_audio": true,
                "has_video": true,
                "label": "1080p MP4 · 音视频合并"
            }
        ],
        "subtitles": ["en", "zh-Hans", "ja"]
    }
}

Response (400):
{
    "success": false,
    "error": "无法解析该链接，请检查URL是否正确"
}
```

### 3.2 下载视频（服务端代理模式）

代理接口下载并准备文件，响应结束后清理本次临时目录。

```
POST /api/download
Content-Type: application/json

Request:
{
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
    "format_id": "137+140"
}

Response: 视频文件流 (Content-Type: video/mp4)
Headers:
  Content-Disposition: attachment; filename="视频标题.mp4"
```

### 3.3 获取直链

直链接口同时返回是否需要代理，浏览器无法直接获取时改用服务端下载。

```
POST /api/direct-url
Content-Type: application/json

Request:
{
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
    "format_id": "137"
}

Response (200):
{
    "success": true,
    "data": {
        "direct_url": "https://rr3---sn-xxx.googlevideo.com/...",
        "ext": "mp4",
        "filesize": 52428800,
        "title": "视频标题",
        "requires_proxy": false,
        "reason": ""
    }
}
```

### 3.4 AI 视频总结（SSE 流式）

总结接口先检查身份与额度，再提取字幕、生成摘要和导图，实时推送处理结果。

```
POST /api/summarize
Content-Type: application/json
Authorization: Bearer <token>

Request:
{
    "url": "https://www.bilibili.com/video/BV1mAAmzqEfP",
    "language": "zh"
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - subtitle  → 字幕数据（含 segments 时间戳列表和 full_text）
  - summary   → 总结摘要（流式 token，逐字输出）
  - mindmap   → 思维导图 Markdown（一次性返回）
  - quota     → 成功结算后的额度快照
  - done      → 完成信号
  - error     → 错误信息
```

可选参数：`video_title`、`platform` 用于保存历史元信息，`transcript_id` 用于显式选择本人已完成的转写字幕。

```
GET /api/summarize/result?url=<视频原始链接>&language=zh
Authorization: Bearer <token>

Response: 本人已保存的字幕、摘要和导图，无结果时 data 为 null
```

### 3.5 AI 视频问答（SSE 流式）

问答使用字幕和最近对话作为上下文，每轮成功后单独结算问答额度。

```
POST /api/chat
Content-Type: application/json
Authorization: Bearer <token>

Request:
{
    "url": "https://www.bilibili.com/video/BV1mAAmzqEfP",
    "question": "这个视频用了什么技术栈？",
    "subtitle_text": ""
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - answer    → AI 回答（流式 token）
  - quota     → 成功结算后的额度快照
  - done      → 完成信号
  - error     → 错误信息
```

可选参数：`history` 为最近的对话消息列表，每项包含 `role`（user / assistant）和 `content`，用于连续追问；问答正文不持久保存。

### 3.6 个人功能与扩展接口

个人功能沿用相同身份和数据归属规则。详细请求、结果结构及处理方式分别维护在用户与扩展方案中。

| 接口入口 | 功能 |
|----------|------|
| `/api/auth/me`、`/api/auth/quota` | 当前身份、四项额度和会员状态 |
| `/api/history` | 本人下载与总结历史 |
| `/api/batches`、`/api/tasks` | 批次、任务状态、进度与文件领取 |
| `/api/subtitles/translate` | 本人保存字幕的逐段翻译 |
| `/api/transcriptions` | 显式语音转写与成功结果 |
| `/api/billing/plans`、`/api/billing/checkout` | 套餐、订单和 Checkout |

账号接口见[用户子系统方案](./【用户与AI额度子系统】方案设计文档.md)，历史、队列、字幕和支付接口见[扩展接口与数据方案](./【剩余扩展】接口与数据方案.md)。

## 4. 下载模式策略

下载优先让浏览器获取源文件，平台要求额外处理时由后端准备。后台任务是用户主动选择的持久下载方式。

1. **直链下载**：查询 `/api/direct-url`，直链可用且无需代理时，由浏览器获取并保存
2. **代理下载**：直链失败、防盗链、分段或需要合并时调用 `/api/download`，完成后返回文件
3. **后台下载**：保存任务 → 排队执行 → 文件准备完成 → 本人领取，关闭页面不取消任务

- **文件状态**：服务端准备完成、已交给浏览器和磁盘保存是不同状态，页面只展示能够确认的结果
- **进度**：后台任务使用真实字节和阶段；未知总量、合并及后处理不推算百分比
- **空间与期限**：后台单文件 2 GiB，临时预算 10 GiB，准备后保留 24 小时，终态任务快照保留 30 天
- **清理**：单条响应结束清理，后台清理避开活跃下载和正在领取的文件，失败或取消后释放临时文件

## 5. 前端页面设计

页面采用蓝白配色、圆角卡片和 A 舒展版布局。桌面视频与 AI 内容并排展示，手机和平板按可用空间切换为纵向布局。

### 5.1 首页与工作台

首页提供链接输入和公开介绍，解析后进入 `/workbench`，集中完成下载与内容整理。

- **页头**：Logo、导航、登录/退出、历史、队列和会员入口
- **首页**：标题、链接输入、支持平台、功能、套餐、操作步骤与问答
- **视频面板**：封面、元信息、可用格式、普通下载和后台下载
- **AI 面板**：摘要、字幕、导图、问答四个标签；游客显示登录引导，登录后先恢复保存结果
- **交互状态**：解析加载、生成过程、可取消请求、失败提示和显式重试

### 5.2 个人页面与公开指南

个人页面只读取本人数据，公开指南介绍操作和限制。退出或换号后清空个人内容，保留当前可公开解析的视频信息。

| 页面 | 内容 |
|------|------|
| `/history` | 下载/总结分类、分页、详情和删除 |
| `/queue` | 批量输入、真实进度、取消、下载重试和文件领取 |
| `/billing` | 服务端权益、套餐、Checkout 和本人订单 |
| `/guide/` | 使用步骤、能力对比、额度、限制与来源 |

## 7. AI 视频总结模块设计

AI 分析以真实字幕为输入，生成过程流式展示。没有字幕时提示用户选择转写，不自动猜测视频内容或启动模型下载。

### 7.1 字幕提取

字幕优先使用平台人工内容，再按语言选择自动字幕；B 站先通过专用接口获取。

```
视频 URL
    ├─ B站 → 专用 API 获取 CC / AI 字幕 → 失败回退 yt-dlp
    └─ 其他平台 → yt-dlp
                    ├─ 人工字幕（zh > en > ja > ko > 其他）
                    ├─ 自动字幕（同上）
                    └─ 无字幕 → 提示主动转写
```

VTT / SRT / JSON3 统一解析为 `[{start, end, text}, ...]`，保留完整字幕用于阅读和导出。

### 7.2 生成与保存

先恢复本人成功结果，无结果或主动重新总结时才预占额度并生成。

1. 提取平台字幕，或读取用户显式选择的本人转写字幕
2. 摘要、导图与问答使用前 15000 字符，页面提示超长分析范围
3. DeepSeek 流式生成摘要，再生成思维导图 Markdown
4. 完整成功后在同一事务保存结果并结算额度，发送 quota 和 done
5. 失败释放未成功预占，保留上次成功结果

### 7.3 SSE 与内容渲染

流式文本按 JSON 编码，避免换行影响 SSE 分块；前端按事件类型解码后展示。

- **SSE**：空行结束一个事件，多行 data 用换行拼接，done 使用 `[DONE]`
- **摘要/回答**：marked 转 Markdown 为 HTML → DOMPurify 清理 → typography 排版
- **字幕**：时间戳分段、展开/收起，导出 SRT / VTT / TXT
- **导图**：markmap 将 Markdown 渲染为 SVG，支持节点折叠、缩放和平移

### 7.4 导图导出

导出使用完整内容边界，用户当前缩放和平移不影响文件范围。

- **边界**：通过根节点 `getBBox()` 计算完整内容，重设 viewBox
- **SVG**：克隆图形、补齐必要样式并序列化为独立文件
- **PNG**：替换 foreignObject 为 SVG 文本，至少 4 倍绘制且宽度不低于 4096 像素，再通过 Canvas 导出
- **全屏**：使用浏览器 Fullscreen API，切换后适应画布

## 8. 扩展功能设计

历史、任务、字幕处理和会员在同一账号与额度体系内运行，详细接口和数据见扩展方案。

- **历史**：直接查询保存结果，删除只影响本人记录和相关恢复内容
- **后台任务**：SQLite 排队，下载并发 2，翻译和转写各 1；取消、重启和重试均更新真实状态
- **字幕翻译**：本人来源、完整分段、时间戳不变，限制 20000 字符与 1000 段
- **本地转写**：显式准备 small / CPU / int8，已有平台字幕不运行，单条最多 30 分钟
- **部署**：基础容器与可选 ASR 分开配置，媒体与文本采用不同保存期限

## 9. 用户与数据设计

账号认证决定数据归属，额度决定当前可执行的 AI 请求。成功结果与用量一起保存，刷新或重登后免费恢复。

- **认证**：bcrypt 哈希保存密码，JWT 配合服务端会话，72 小时有效，退出撤销当前会话
- **免费额度**：总结 3 次、问答 10 次、翻译 3 次、转写 60 分钟/日，四项独立
- **VIP 额度**：总结 30 次、问答 100 次、翻译 20 次、转写 240 分钟/日
- **结算**：先预占、完整成功才计量，失败或完成前取消释放；北京时间零点换日
- **存储**：SQLite 保存账号、用量、历史、成功文本、任务和订单，升级先备份，不清空原数据

认证接口、会话、恢复和并发规则见[用户子系统方案](./【用户与AI额度子系统】方案设计文档.md)。

## 10. 会员与支付设计

会员通过服务端确认的付款开通，不凭前端状态授予权益。当前商品为测试环境 CNY 990 分 / 30 天，不自动续费。

```
创建订单 → Stripe Checkout → 用户付款 → 签名回调
    → 核对环境、订单、商品、金额和币种 → 保存订单与会员权益
```

- 重复回调不重复授予，续购从已有有效到期时间与付款时间的较晚者增加 30 天
- 缺配置或未付款不开放权益，页面回跳只查询服务端结果
- 到期恢复免费上限，当天已用量不清零，合法预占任务按原授权完成
- 全额退款或争议撤销对应订单权益，部分退款转人工处理
- 默认使用 Stripe 测试支付，正式收款尚未验证

## 11. SEO 与 GEO 设计

公开介绍在构建时生成完整 HTML，个人页面继续通过认证接口使用。站点地址、页面信息和公开正文统一维护。

- **公开内容**：首页与 `/guide/` 共用产品说明和问答，禁用 JavaScript 仍可阅读
- **页面信息**：标题、描述、OG / Twitter 分享信息与结构化数据
- **站点地址**：通过 `VITE_SITE_URL` 在构建时配置，没有正式域名时不索引、不生成虚构网址
- **个人页面**：初始响应标记 noindex，不进入网站地图，公开内容不含个人资料
- **上线检查**：未知路径返回 404，检查 HTTPS、抓取与真实收录；AI 引用需公开上线后观察

配置与维护方法见[SEO 与 GEO 运行指南](./SEO与GEO运行指南.md)。
