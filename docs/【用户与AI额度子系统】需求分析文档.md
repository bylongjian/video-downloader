# SaveAny 用户与 AI 额度子系统——需求分析文档

本子系统把原型中的登录入口和每日额度变成真实能力：用户可以注册、登录和退出，服务端决定谁能调用 AI，并且只对成功完成的请求计次。视频解析和下载继续向游客开放，账号与额度不会改变已有的视频下载流程。

本文根据当前项目、只读参考项目 `../free-video-downloader` 和用户本轮确认整理，日期为 **2026-11-01**。批次一至六及验收反馈中的成功结果持久恢复均已完成，用户已确认“验收通过”；技术验证和清理记录见配套方案第 8 章。

## 1. 需求小卡与完成标准

开发前的 MVP 已能下载视频并使用 AI，账号和额度尚未接入。本轮已完成真实账号、模型调用次数管理和成功结果恢复，为后续历史记录提供用户归属基础；会员继续保留后续开放提示。

| 项目 | 本次约定 |
| --- | --- |
| 子系统范围 | 邮箱密码注册、登录、会话恢复、退出、每日 AI 额度、服务端权限与页面提示 |
| 目标效果 | 重启后账号和已用次数仍在；前端不能自行修改权限或额度 |
| 免费额度 | 每人每天 **3 次总结、10 次问答**，两项独立计算 |
| 一天的边界 | **Asia/Shanghai，北京时间零点**；采用服务端时间 |
| 计次原则 | 完整成功才计一次；生成失败不计次；执行中暂时预占名额，避免并发超用 |
| 数据保存 | SQLite 保存账号、登录会话、额度和按账号隔离的成功总结结果（字幕、摘要、导图）；不保存视频文件或问答正文 |
| 第一个可操作样品 | 在现有页面注册、登录，刷新后恢复身份，退出后恢复游客状态；保留当前视频链接 |
| 首个完整业务样品 | 游客解析视频 → 登录 → 继续总结 → 成功后总结剩余 2 次 → 问答后问答剩余 9 次 |
| 本次交付边界 | 两份子系统文档、批次一至六实现及成功结果持久恢复；已通过用户验收，用户已要求保存本地 Git 记录，未授权推送或发布 |

最重要的五条预期是：真实账号可以持久保存；AI 权限由服务端检查；总结与问答额度互不挤占；失败不扣次且并发不超用；登录和额度错误不影响视频解析与下载。

## 3. 用户、功能范围与权限

本次只区分游客和已登录免费用户，不把尚未实现的会员能力混入额度判断。用户不登录也能完成最基本的视频保存，登录只影响需要调用模型的功能。

| 能力 | 游客 | 已登录免费用户 |
| --- | --- | --- |
| 视频解析、格式选择、获取直链和代理下载 | ✅ 可用 | ✅ 可用 |
| AI 总结与思维导图生成 | 提示登录，不调用模型 | 每日完整成功 3 次 |
| AI 连续问答 | 提示登录，不调用模型 | 每日完整成功 10 轮，每轮成功回答计一次 |
| 查看当前页面已有字幕及导出 | 不额外计 AI 次数；退出时清理上一账号内容 | 不额外计 AI 次数 |
| 恢复同账号同链接、同语言的成功总结 | 需先登录 | 免费恢复字幕、摘要和导图，额度用尽也可读取 |
| 主动重新总结同一个视频 | 需先登录 | 每次完整成功计一次并替换保存结果；失败保留上次成功结果 |
| 查看剩余额度 | 不展示他人额度 | 从服务端获取本人两项额度 |
| 注册、登录、退出 | 可注册和登录 | 可退出，注册登录弹窗可切换 |
| VIP 开通、历史记录 | 后续批次 | 后续批次 |

字幕提取目前包含在总结接口中。本次不新增独立字幕接口：游客或额度不足时，不启动新的总结请求，也不会为此单独提取字幕；已登录且有总结名额的用户若遇到无模型密钥或模型失败，仍可查看已经收到的字幕，且不计次。登录或额度失败不会禁止视频下载。

## 4. 核心功能需求

下面的编号用于让设计、开发批次与验收相互对应。除表中规则外，不增加找回密码、邮箱验证码、第三方登录、后台管理或支付能力。

### 4.1 R1：注册与登录

用户用邮箱和密码创建真实账号，注册成功即进入登录状态。重复邮箱要明确提示，密码错误与邮箱不存在使用同一条登录失败提示，避免用户误以为是系统故障。

| 编号 | 要求 | 可观察结果 |
| --- | --- | --- |
| R1.1 | 邮箱在 HTTP 输入处校验，去除首尾空白并按大小写不敏感规则查重 | 相同邮箱不同大小写不能注册两个账号 |
| R1.2 | 首版密码 8～50 个字符，UTF-8 编码不超过 72 字节；不自动去空格、不截断 | 页面说明要求，服务端返回清楚的输入提示 |
| R1.3 | 只存带随机盐的密码哈希；不返回密码哈希 | 数据库和接口中没有明文密码 |
| R1.4 | 注册成功自动登录；登录成功加载当前用户与额度 | 页头出现本人邮箱，显示两项真实剩余次数 |
| R1.5 | 弹窗支持登录/注册切换、密码显隐、执行中禁用、Esc 关闭和焦点返回 | 手机和键盘操作可完成注册登录；不提供演示账号 |

密码长度是本次方案提出的首版输入规则，随两份文档一并审阅；bcrypt 的字节上限在输入处处理，避免把库异常暴露给用户。

### 4.2 R2：恢复登录与退出

刷新页面后先向服务端核实身份，再查询本人已保存的成功结果。已有结果直接恢复，不提取字幕、不调用模型、不扣次。退出撤销当前会话并清理页面内容和进行中的请求，但保留服务端成功结果；视频链接和可下载信息继续保留。

| 编号 | 要求 | 可观察结果 |
| --- | --- | --- |
| R2.1 | 登录有效期首版为 72 小时；刷新时以 `/api/auth/me` 为准 | 有效会话恢复登录；过期或已撤销会话要求重新登录 |
| R2.2 | 退出调用服务端撤销当前会话，再清理本地 Token | 旧 Token 再访问受保护接口返回 401 |
| R2.3 | 其他独立登录会话不受当前退出影响 | 在另一浏览器独立登录的用户仍可使用 |
| R2.4 | 同源标签页共享同一次登录；退出或切换账号时同步清理旧内容 | 不继续展示上个账号的额度、对话或尚在回传的答案 |
| R2.5 | 网络故障与登录过期区分处理 | 网络故障提示重试；不自动把故障伪装成成功退出或密码错误 |

### 4.3 R3：每日两项额度

总结和问答分别计数。切换视频不会重置额度，服务重启也不会把已用次数归零，修改浏览器时间或本地存储不能获得额外次数。

| 编号 | 要求 | 可观察结果 |
| --- | --- | --- |
| R3.1 | 总结每天 3 次，问答每天 10 次，按服务端北京时间零点换日 | 两项余额独立展示，提供明确的恢复时间 |
| R3.2 | 一次总结包含摘要与思维导图；两项都成功才计一次 | 不按两个模型调用扣两次，也不对字幕和导出单独扣次 |
| R3.3 | 一次问答是一次正常结束的回答，多轮追问逐轮计次 | 总结剩余不随问答减少 |
| R3.4 | 无字幕、未配置密钥、模型失败、空输出或输出被截断不计次 | 页面保留已收到的可用内容并允许重试 |
| R3.5 | 摘要已生成但导图失败，也视为本次总结失败 | 总结次数不减少，页面说明内容不完整 |
| R3.6 | 执行中预占一个名额；剩余额度为上限减成功次数减有效预占数 | 最后一个名额不能被两个同时请求都用掉 |
| R3.7 | 已开始的请求归属于其预占时的北京时间日期 | 午夜前开始、午夜后完成的请求结算到前一天；新一天可用新额度 |
| R3.8 | 进程异常遗留的预占可在到期后释放，过期任务不得再成功结算 | 重启或中断不会永久占住免费名额 |

正式计次的完成点是：服务端已取得完整结果，并把请求状态保存为成功，随后发送 `quota` 和 `done`。在此之前取消或失败会释放预占；若服务端已经完成计次，最后一个网络包丢失不撤销成功记录，用户可刷新额度核实。应用次数与模型提供商实际费用不是同一件事，失败请求可能已消耗提供商用量，但不扣用户免费次数。

### 4.4 R4：服务端权限与错误恢复

前端按钮禁用只用于改善体验，不能代替权限检查。即使绕过页面直接请求接口，服务端也必须拒绝匿名、过期会话和额度不足的 AI 调用。

| 场景 | 约定结果 |
| --- | --- |
| 未登录、Token 无效/过期/已撤销 | SSE 开始前返回 HTTP 401；不提取字幕、不调用模型、不预占额度 |
| 对应额度已经用尽或全部被执行中请求预占 | SSE 开始前返回 HTTP 429，区分“今日用完”和“请求处理中”；不调用模型 |
| 用户或额度数据暂不可用 | 返回可重试错误，不按游客放行、不按无限额度放行 |
| SSE 已开始后无字幕或模型失败 | 发送带原因的 `error`，释放未成功的预占，不发送 `done` |
| 已取得摘要、字幕等部分结果 | 同一账号的当前页面可继续阅读、复制或导出；不伪称完整成功 |
| 用户点击返回首页、更换视频或退出 | 取消旧请求，不把迟到的内容写入新视频或另一账号页面 |

### 4.5 R5：登录后继续当前操作

登录应服务于用户当前正在看的视频。工作台恢复身份期间显示准备状态；游客先看到登录引导，用户登录成功后只继续当前有效的一次待办操作。

| 触发方式 | 期望行为 |
| --- | --- |
| 游客解析成功 | 视频可立即下载；AI 面板显示“登录后生成总结”，不反复自动弹窗 |
| 点击登录后生成总结 | 登录成功后，在 URL 仍相同的情况下自动执行一次总结 |
| 直接从页头登录 | 恢复账号；当前视频尚无总结时继续一次自动总结 |
| 登录途中更换视频 | 取消旧待办，只对当前视频决定是否生成 |
| 额度用尽 | 显示对应额度及明日恢复时间；另一项仍有额度时可继续使用，不强制购买 VIP |
| 刷新工作台或退出重登 | 原有链接保留；同账号已有成功结果直接恢复，不自动再次生成、不扣次 |

用户于 2026-11-01 验收时要求并确认：同一账号总结完成后，退出重登、刷新或重启服务都优先恢复成功结果；只有主动选择“重新总结”才再次生成和计次。没有保存结果的新视频沿用首次自动生成流程。恢复查询故障只能提示重试，不能当成无结果自动调用模型。保存结果与计次在同一事务完成；失败不覆盖旧结果。本次不提供历史列表，也不持久保存问答。旧版本未落盘的结果无法凭空补回，新规则适用于更新后成功保存的结果。

## 5. 数据、界面与运行要求

本次保存账号、额度和成功总结结果，支持同账号免费恢复；不提前建设历史列表或视频文件库。新增提示继续使用已确认的蓝白风格、16px 正文和最大 1760px 内容区，保持现有四个 AI 标签与手机布局。

| 编号 | 要求 | 验收依据 |
| --- | --- | --- |
| R6 | SQLite 持久保存账号、会话和额度记录，用户之间隔离 | 两个测试账号、服务重启与真实临时数据库测试 |
| R7 | 登录密钥从服务端环境读取，不硬编码，不向前端返回 | 配置模板无真实密钥，接口无敏感字段 |
| R8 | 浏览器只保存登录 Token；邮箱、额度以服务端刷新为准，不保存密码或 AI 正文 | 刷新和账号切换检查；修改本地数据不能绕过限制 |
| R9 | 免费套餐明确标注 3 次总结和 10 次问答；VIP 说明后续开放 | 首页、工作台页脚和手机入口用语一致 |
| R10 | 保留现有核心回归测试；新增测试隔离模型与视频平台 | 测试不加载本机真实 `.env`，不消耗模型额度 |
| R11 | 提供实际 PowerShell 启动步骤、手工验收表；用户验收后清理临时材料 | 自动测试证据与人工体验结果分别记录 |

按本轮确认新增服务器端成功总结保存；不引入对话持久化、历史列表或独立状态框架。注册不发送验证邮件，用户需自行记住密码；找回密码和邮箱验证不属于首版完成标准。

## 6. 用户验收场景

验收先检查最短真实路径，再检查费用相关的失败与并发行为。真实模型的少量联调只使用本项目已配置的密钥；错误、额度耗尽和日期边界优先通过隔离测试验证，不为验收连续调用大量付费请求。

| 编号 | 操作 | 应该看到什么 |
| --- | --- | --- |
| A1 | 游客打开应用，解析并下载公开视频 | 下载正常，AI 显示登录引导，没有模型请求 |
| A2 | 从工作台注册新邮箱 | 自动登录，视频链接保留，总结和问答额度分别为 3、10；待办总结开始后有执行中提示 |
| A3 | 完成一次有字幕视频总结 | 摘要与导图正常，总结已用 1、剩余 2，问答仍剩余 10 |
| A4 | 连续追问两轮 | 回答流式显示且第二轮带历史；问答剩余 8，总结仍剩余 2 |
| A5 | 让导图生成失败，或使用无字幕视频 | 明确显示未完成，预占释放，不增加总结已用次数；视频仍可下载 |
| A6 | 总结额度为零但问答有余额 | 总结说明明日恢复；当前已有字幕的问答仍可用；没有字幕时明确提示上下文不足 |
| A7 | 最后一个名额同时提交两次请求 | 只有一个获准执行，另一个收到处理中或用尽提示，不超扣、不超额成功 |
| A8 | 成功总结后退出重登三次、刷新页面，再重启后端 | 身份重新核实，字幕、摘要和导图恢复；无总结请求、用量不变；主动重新总结成功才加一次，失败保留旧结果 |
| A9 | 退出，再使用刚才的 Token 请求 AI 或 `/me` | 返回 401，旧答案不再进入页面；游客下载仍可用 |
| A10 | 使用另一个账号登录 | 展示另一账号额度，不展示上个账号的 AI 内容 |
| A11 | 隔离测试跨过北京时间零点，并处理一条跨日任务 | 新一天获得独立额度；旧任务只结算到预占日期 |
| A12 | 缩至 375px，使用键盘完成弹窗与四个标签操作 | 字号可读，按钮无遮挡，Esc 和焦点恢复正常 |

验收失败时记录场景编号、操作、预期和实际提示。自动测试通过不能替代用户对登录流程与额度提示的体验确认。

## 7. 开发顺序与后续范围

本子系统位于 MVP 扩展第一优先级，先完成身份，再完成额度与真实 AI 接入。详细文件清单、测试命令和每个批次的进入条件见[方案设计第 8 章](./【用户与AI额度子系统】方案设计文档.md#8-分阶段开发计划批次一至批次六)。
